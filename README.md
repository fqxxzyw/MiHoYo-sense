# MiHoYo Sense

面向米哈游游戏社区的内容理解、玩家评论分析与个性化内容推荐学习项目。

项目计划整合米游社、B站与抖音中关于《原神》《崩坏：星穹铁道》《绝区零》的文章、视频文本与评论，分析玩家讨论的主题、态度和兴趣，并探索跨平台差异与内容推荐。

> 当前阶段：米游社三个游戏的帖子发现、单帖采集、有限批量采集与断点恢复。其他平台、清洗与建模仍为待办。
> 最后更新：2026-10-18。
> 本轮仅完善采集功能和文档。已有远程仓库实际包含旧采集代码及原始样本；新增原始数据保持本地，不随本轮代码交付。代码实现、真实接口验证和远程发布分别记录。

## 项目目标

- 理解文章和视频在讨论什么：剧情、角色、攻略、联动、活动、二创等。
- 分析评论的讨论对象、情感态度与兴趣信号。
- 比较相同游戏、相同事件在不同平台上的讨论差异。
- 根据一条评论或平台内的历史评论，推荐相关内容并给出推荐理由。
- 完成从数据获取、EDA、清洗、标注、建模到推荐评估的学习实践，形成可复现的实验记录。

第一版以文本为主。视频标题、简介、字幕或转写文本应分别记录；音频和画面理解作为后续扩展，不列为首版必须完成项。

## 三游戏采集的运行方式

在项目根目录、已激活的 `hoyosense` 环境中执行：

```powershell
# 只展示三游戏首页第 1 页发现结果，不启动评论采集。
python scripts/01_collect_miyoushe.py --discover-posts --game all

# 只分页发现更多帖子：每游戏累计检查最多 10 页，不启动正文或评论采集。
python scripts/01_collect_miyoushe.py --discover-more --game all --max-discovery-pages 10

# 小规模批量：每游戏最多 3 帖，每帖顶层最多 5 页；最多处理 3 个楼层，各 2 页。
python scripts/01_collect_miyoushe.py --batch --game all --max-posts 3 --max-pages 5 --max-sub-pages 2 --max-floors 3

# 再次运行同一条批量命令：复用清单与已保存页，从未完成的断点继续。
```

批量运行自动接通分页发现，优先引用已有第一页原始响应，从下一页继续。
默认累计发现页数上限为 10，支持 `--max-discovery-pages None`，不影响已有四种采集上限。
批次默认保存在 `data/raw/miyoushe/_batches/genshin_starrail_zzz/batch_manifest.json`，
单帖仍保存在 `data/raw/miyoushe/<game>/<post_id>/full_collection/`。
旧批次中的候选及其顺序保留，新发现的帖子追加到末尾。
`--max-posts 3` 指累计前 3 帖，重复运行不会自动换成后 3 帖。
上限更大时会继续已有任务；不要把 `limited`（达到上限）当作 `completed`（当前接口与条件下遍历结束）。

采集原始 JSON，正文 HTML、图片链接、空文本评论和回复关系均保留；不下载图片。
本次默认上限有限，显式传 `None` 才取消对应上限。发现返回空页时停止；重复页没有新任务 ID 时停滞并保留 raw。
分页详情、旧批次升级和停止原因见 [更多帖子发现](docs/miyoushe_discovery.md)。
详细参数、异常处理、样本验证结果见 [采集说明](docs/miyoushe_collection.md)。

### 配置与路径

| 文件 | 职责 |
| --- | --- |
| `configs/miyoushe.json` | 修改原始、处理、标注、划分、输出目录，以及四种采集上限 |
| `src/hoyo_sense/config.py` | 统一定位项目根目录、解析路径、校验配置，供后续清洗/分析复用 |
| `src/hoyo_sense/endpoints.py` | 按平台保存已验证接口；B站、抖音暂为空分组 |
| `src/hoyo_sense/games.py` | 统一游戏名称及米游社自己的游戏 ID |
| `src/hoyo_sense/miyoushe_discovery.py` | 分页发现、发现断点核验、重复页防止循环 |
| `src/hoyo_sense/storage.py` | 共用原子 JSON 保存、文件哈希核验和文件锁 |
| `scripts/01_collect_miyoushe.py` | 读取配置并执行采集，保留原有单帖与发现逻辑 |

默认 `raw_dir` 是 `data/raw`，实际米游社数据写入 `data/raw/miyoushe/<game>/`。
配置与 CLI 中所有相对路径都基于项目根目录，**不依赖当前工作目录**；绝对路径直接定位。
使用 `pathlib.Path` 拼接路径，不写死开发者的盘符。配置不会移动或删除旧文件，也不会自动创建空的分析目录。

优先级：**显式命令行参数 > 指定配置文件 > 默认配置**。例如：

```powershell
# 指定配置，并临时把每游戏帖子上限改为 1。
python scripts/01_collect_miyoushe.py --config configs/miyoushe.json --batch --game all --max-posts 1

# 临时换一个米游社原始数据根目录；其下直接是 genshin/starrail/zzz。
python scripts/01_collect_miyoushe.py --batch --game all --raw-root data/raw/miyoushe_trial
```

JSON 中 `null` 表示取消对应上限，命令行写 `None`。未知配置键、负数、浮点或布尔上限会报错。
原始与处理等目录不允许相同或互相包含，以免后续清洗覆盖采集源文件。
`.gitignore` 默认覆盖 `data/raw/` 等标准目录；若改为其他项目内目录，需要把新目录也加入忽略规则。

请求节奏在同一配置文件的 `request` 中设置，和采集数量上限分开：

```json
"request": {
  "interval_seconds": 2,
  "timeout_seconds": 20
}
```

每个串行网络请求前等待 `interval_seconds` 秒；`timeout_seconds` 是 Requests 的连接/读取超时参数，
不是每隔多少秒发请求，也不是整次下载的严格总时限。旧配置没有 `request` 时仍使用 2 秒 / 20 秒。
若已把四个采集上限设为 `null`，添加请求配置时保留原值，不用恢复成示例里的有限上限。
请求间隔不保证不会被拒绝；403 停止检查原因，429 显示服务端 `Retry-After` 并停止保存断点，不自动重试。
同时运行多个采集进程会叠加请求频率，本阶段继续采用单进程串行采集。

接口地址不带 `gids`、`post_id`、`floor_id` 或 `last_id`，这些值由采集函数通过 `params` 传入。
米游社三游戏共用接口，使用 `games.py` 中的 `gids` 映射；不要为每个游戏复制整套采集代码。
本次拆分仅改变地址来源与请求设置，不更改 raw 保存方式、分页或已有断点格式。

新增帖子发现上限在与 `collection` 平级的配置中设置：

```json
"discovery": {
  "max_pages": 10
}
```

`max_pages` 是累计发现的列表页数，包含已有第一页和空的停止页；它与 `collection.max_pages`（每帖顶层评论页数）不同。
设置 `null` 或运行时传 `--max-discovery-pages None` 可取消发现页数上限；四个原有 `collection` 值保持用户设置。
旧配置缺少 `discovery` 时默认使用 10 页，不需要重建已有 raw 或删除断点。

这些数字是发现的候选帖子数量，本轮真实验证没有批量抓取这些新帖的正文与评论。
